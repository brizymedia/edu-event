# 이벤트와 교육연구소 블로그 작업 설명서

사이트의 **블로그**(`/blog/`)에 정보 글을 올릴 때 따르는 규칙이다. HD기획 `_blog/GUIDE.md` 를 이 사이트에 맞게 옮겼다(지역별 글 → **주제 글**). 사람이 고칠 때도 이 문서를 먼저 고친다.

- 읽는 사람: 행사를 맡은 담당자(학교 · 유치원 · 기업체 · 기관 · 교회)와 교육을 고민하는 선생님.
- 목표: 네이버 · 구글 · AI 검색에서 인용되기 좋은, 담당자가 **저장해 두고 싶은 체크리스트**. 광고 글이 아니다.
- 원칙: 틀린 정보 한 줄이 글 한 편보다 해롭다. **확인 못 한 것은 쓰지 않는다.** 그럴듯하게 지어낸 사실 · 회사 약속 · 교육 효과가 가장 위험하다.

## 1. 순서
1. 주제는 `_blog/keywords.json`(분야 event/edu, 핵심 키워드 `k`). 아직 안 쓴 주제를 고른다.
2. 법 · 기준 · 기관 이야기는 `_blog/sources.json` 의 출처와 그 `사실` 범위 안에서만. 새 출처는 **사람이(또는 도구로) 직접 열어 확인한 뒤** sources.json 에 추가한다. 확인 못 하면 그 내용은 쓰지 않는다(이번에 진로교육법은 공식 사이트에서 조문을 못 열어 뺐다).
3. 회사 이야기는 `_blog/company.json` 의 문장 범위 안에서만.
4. `_blog/posts/<날짜>-<slug>.json` 을 쓴다(3장). `근거` 를 채운다.
5. `node scripts/blog-check.mjs` (또는 `--new 파일`) 통과할 때까지 고친다. 통과하려고 사실을 꾸미지 않는다 — 안 되면 글을 버린다.
6. **`python tools/build_site.py` 다음에 `node scripts/build-blog.mjs`** → `blog/`, `rss.xml`, `sitemap.xml` · `llms.txt` 의 블로그 부분이 갱신된다. 결과 HTML 은 손으로 고치지 않는다.
7. 커밋. 푸시 · 검색 등록은 사람이.

## 2. 절대 쓰지 않는 것 (검사기가 상당수를 막는다)
- 가격 · 단가 · ○○원 · 무료 · 할인 · 당일 회신 등 대표가 준 적 없는 약속. 회사가 할 수 있다고 말하는 것은 4장뿐.
- 후기 · 고객 발언 · 만족도 · 평판 · 1위 · 보장 · 100%.
- 교육 **효과 단정**(향상됩니다 · 개선됩니다 · 효과가 있다), 의학 표현(치료 · 진단 · 처방 · 치유; 「심리치료상담」 전공 표기는 예외), 출처 없는 연구 · 통계 · 퍼센트 · 「전문가들은」.
- 경험 늘려 말하기(「~해 왔습니다」). 확인된 숫자(학교 94곳, 20년)만.
- 사진 설명에 학교 이름 · 장소 · 연도를 지어 쓰기. 캡션은 포트폴리오 제목 그대로.
- 소장 논문의 **결과**를 말하기(제목만 쓴다). 다른 업체 이름 · 비교.
- 작성자용 메모(「나중에 고치겠다」 등).

## 3. 글 형식 (JSON)
| 칸 | 규칙 |
|---|---|
| `slug` | 한글 · 영소문자 · 숫자와 `-`, 70자 이하 |
| `date` | `YYYY-MM-DD`, 오늘 이전. 파일 이름 `<date>-<slug>.json` |
| `category` · `topic` | keywords.json 의 것. topic 은 한 번만 |
| `title` | 15~50자, 핵심 키워드 통째로 |
| `description` | 70~160자, 핵심 키워드 포함 |
| `keyword` | `{ "main": keywords.json 의 k 그대로, "sub": [] }` |
| `lead` | 80~420자, 첫 문단에 핵심 키워드와 결론 |
| `points` | 3~5개. 본문을 안 읽어도 답이 되는 문장 |
| `cover` | 선택. `{ path, alt, caption }` (사진을 못 쓸 글은 없어도 된다) |
| `sections` | 4~8개. `{ h2, blocks }`. 표 1개 이상 |
| `faq` | 2~6개 (FAQPage JSON-LD 가 된다) |
| `근거` | 2개 이상. `{ 내용: 본문에 그대로 있는 구절, 출처: "company.json" 또는 이 글 sources 의 주소 }`. company.json 근거 1개 이상, sources 를 달았으면 그 출처 근거도 |
| `sources` | `{ name, url }` — sources.json 의 주소 그대로. 없으면 `[]` |

blocks: `{p}` `{ul}` `{ol}` `{table:{head,rows}}` `{img:{path,alt,caption}}` `{tip}`. 꾸밈은 `**굵게**` 와 `[글자](/event.html 또는 https://…)` 뿐. 내부 링크는 `/event.html` 처럼 루트 기준으로 쓰면 빌더가 상대 주소로 바꾼다. 본문에 `/event.html` 또는 `/education.html`, 그리고 `/contact.html` 또는 `/quote.html` 링크가 꼭 있어야 한다.
분량 본문 1800자 이상(2500자 권장). 합니다체, 짧은 문장, 쉬운 말. 첫 문단이 답이다.

## 4. 쓸 수 있는 회사 사실
`_blog/company.json` 의 `사실` 문장이 전부다(소장 이력, 운동회 94곳 · 2011년부터, 행사 · 교육 종류, 사전 상담 · 현장 답사, 실내 대체 프로그램, 현장 사진 전달, 소장 직접 진행). 이 밖의 약속(가격 · 무료 · 당일 회신 등)은 만들지 않는다. 회사를 주어로 한 문장은 검사기가 위 약속 키워드가 있는지 본다.

## 5. 사진
`_blog/photos.json` 의 사진(g01~g10, story-2011; g09 는 얼굴 클로즈업이라 제외)만. 캡션은 「제목 — 무엇을 보여 주는지」, 제목은 photos.json 의 `제목`(포트폴리오 이름) 그대로. 한 글에서 같은 사진 두 번 금지.

## 6. 이 사이트에서 바꾼 것 (HD기획 대비)
- 지역(regions.json) 규칙을 없애고 `category`(행사/교육) · 주제 글 중심. 지역 이동시간 같은 확인 안 된 사실은 쓰지 않는다.
- 회사 사실 근거(company.json), 효과 · 의학 · 통계 표현 금지, 사진 캡션 제목 고정 규칙을 추가.
- 주소 · noindex · 머리글 · 바닥글은 `tools/blog_shell.py` 가 `tools/build_site.py` 에서 읽는다(여기에 도메인을 적지 않는다). 링크는 상대 주소.
- 도메인이 정해지면 `tools/build_site.py` 의 BASE · NOINDEX 를 바꾸고 `build_site.py` → `build-blog.mjs` 순으로 다시 돌린다. IndexNow 키 파일은 도메인이 정해진 뒤에 만든다.
